# MLB Ballpark Effects: Bayesian Hierarchical Model

Estimates how much each MLB ballpark inflates or suppresses run scoring, with uncertainty, using 2024–2025 regular-season results.
Link to presentation - https://canva.link/dm9ixcbjjqa09px

## Research question

How much does each park change run scoring, how uncertain are those estimates, and how do they compare to traditional park factors?

## Approach

1. **Data collection.** Completed regular-season games for 2024 and 2025 are pulled from the MLB StatsAPI (`MLB-StatsAPI` package). Each game becomes two rows (home and away team), each with the venue and runs scored.
2. **Cleaning.** Renamed venues are mapped to one canonical name, and only games at MLB home parks are kept. The result is saved to `mlb_runs_data_30.csv`.
3. **Model.** A hierarchical Poisson model in PyMC with a log link:
   - `alpha`: league-wide baseline (log runs per team-game)
   - `beta[park]`: park effect, partially pooled toward zero with a shared `sigma` (HalfCauchy prior)
   - `runs ~ Poisson(exp(alpha + beta[park]))`
   - Sampled with NUTS (2,000 draws, 1,000 tuning steps, `target_accept=0.9`).
4. **Diagnostics.** Trace plots, R-hat, and a posterior predictive check.
5. **Outputs.**
   - Posterior mean and 95% credible interval for each park's effect on log runs
   - An interactive plot of park effects (Plotly), colored hitter-friendly vs pitcher-friendly
   - Posterior density plots
   - A comparison against the traditional park factor (average runs at the park divided by league average)

Park effects are on the log-run scale, so `exp(beta)` is the multiplicative effect on expected runs.

## Usage

1. Open `mlb_ballpark_effects.ipynb` in Jupyter.
2. Run the cells in order. The data pull makes one schedule request per season and takes a few minutes.
3. Sampling runs after the data is saved. Check that R-hat is close to 1.00 before reading the park effects.

## Interpreting the results

- A positive mean means the park raises scoring above the league baseline, and a negative mean means it suppresses scoring.
- If a park's 95% interval includes zero, the data can't separate it from an average park. A single point estimate hides this.
- Partial pooling pulls estimates for parks with less data toward the league average, which prevents extreme values from small samples.

## Known limitations and next steps

- **Overdispersion.** Runs per team-game are more variable than a Poisson allows. A negative binomial likelihood would give better-calibrated intervals.
- **Team-quality confounding.** Park effects currently absorb the home team's offense and defense. Adding home and opponent team effects, or comparing each team's home and road games, would isolate the park.
- **Stadium changes.** Temporary and renamed home venues (for example the Athletics' move from Oakland to Sutter Health Park, and the Rays' temporary home in 2025) need to be treated as separate parks. Check the printed venue list for dropped or merged parks.
- **Sample size.** Two seasons is thin for park estimates. More seasons would help.
- **Not modeled.** Weather, batter handedness, and in-season park changes.
